压力夹具只测试执行层资源防线，不经过生产SQLGuard；生产Guard不会批准这种笛卡尔积。SQL和超时结果正确不代表完成生产规模并发或故障恢复压测。

### EXPLAIN限制

仅授权视图SELECT的MySQL账号执行EXPLAIN会返回1345，授SHOW VIEW仍需底表SELECT。为保留隔离，本实现不授底表权限；仅此错误显式记录`execution_checks.explain=unavailable_view_permissions`后继续受限执行，其他EXPLAIN错误失败。

因此这些查询完成了只读执行及结果核对，**没有完成执行计划预检**。详细初始化和权限证据见[MySQL报告](mysql-initialization-check.md)。

## 4. 模型验证边界

- 当前运行配置`MODEL_MODE=mock`，前端有明确演示标识。
- SQL由规则生成，金额、件数、工时等由MySQL执行计算，没有硬编码业务结果。
- HTTP契约测试使用本机HTTP协议夹具，以两个不同MODEL_NAME请求同一业务链，均得到真实MySQL的17000.00结果。
- 该HTTP服务是测试夹具，不是神经网络模型或真实微调模型；不以此宣称模型准确率、幻觉率或微调提升。
- 真实模型地址、访问凭证、权重和adapter尚未提供；配置接入后必须按冻结集做业务验收。

规则演示支持常见统计及明确格式的截至日比例，复杂/无法证明的SQL会澄清或失败。它不等同于一般自然语言理解。SQLGuard只保证已实现的结构规则，不能数学证明任意SQL业务正确；保守拒绝的复杂等价写法可通过一次修复改写为显式关联与预聚合。
